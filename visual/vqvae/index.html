    VQ-VAE + PixelCNN Prior — Visual Guide¶

    The VQ-VAE turns each ECG into a sequence of discrete code indices (stage 1), and a separate autoregressive model learns which index sequences are likely (stage 2). Generation samples indices from the prior and decodes them. Code: src/ecgen/families/vqvae/, losses: src/ecgen/families/vqvae/losses.py. Written reference: VQ-VAE + Prior.

    Stage 1: how the loss is computed¶

    recon, vq_loss, indices = vqvae(x)
total, recon_loss, vq_loss = vqvae_loss(recon, x, vq_loss)   # total = recon_loss + vq_loss
    \[ \mathcal{L} = \underbrace{\operatorname{MSE}(\hat{x}, x)}_{\texttt{recon\_loss}} + \underbrace{\operatorname{MSE}(\operatorname{sg}[z_q],\, z)}_{\text{trains the encoder}} + \beta \cdot \underbrace{\operatorname{MSE}(z_q,\, \operatorname{sg}[z])}_{\text{trains the codebook}}, \qquad \beta = \texttt{commitment\_cost} = 0.25 \]

    β is on the codebook term here

    The original VQ-VAE paper puts β on the encoder (commitment) term. In VectorQuantizer.forward, β multiplies the term that updates the codebook, even though that variable is named commitment_loss. The diagram shows what the code does.

    Stage 2: the PixelCNN prior¶

    PriorLightning loads the stage-1 checkpoint, freezes it, and turns every training ECG into its 625 code indices. PixelCNNPrior is then trained to predict each index from the ones before it.

    Each gated block¶

    Why logit t never sees code t¶

    Hover over (or tap) a top node to see which codes it depends on. This toy stack has three layers with dilations 1, 2, 4; the real prior has ten (1 … 512).

    Sampling¶

    PixelCNNPrior.sample() fills the 625 positions left to right. At step t it runs the network on the codes so far, takes the logits at t, divides by temperature, and draws one code. Then the frozen VQ-VAE decodes all indices at once. Lower temperatures make the most likely code win more often.
